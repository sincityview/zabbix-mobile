# Zabbix Monitor для Android

Клиент Zabbix API для телефона: список текущих проблем, настройки подключения,
фильтр по важности. Написан на Kotlin + Jetpack Compose, собирается в CI и
ставится как APK.

Показывает ровно то же, что страница **Monitoring → Problems** в веб-интерфейсе
Zabbix: подавленные проблемы, проблемы-симптомы, проблемы выключенных хостов и
зависимых триггеров скрыты так же, как там.

## Возможности

- список проблем с цветной полосой важности; тап по строке — подробности
  (время, хост, текст, важность, статус, подтверждение);
- недавно восстановленные проблемы помечены «решено» и приглушены — их Zabbix
  тоже показывает, пока не истёк «OK period»;
- обновление: кнопкой, жестом «потянуть вниз» и автоматически с интервалом из
  настроек (по умолчанию 60 с, только на переднем плане);
- счётчик в шапке — `показано/всего`; по нажатию открывается показ по важности
  (все / Disaster / High / Average / Warning / Information / Not classified);
- настройки: URL сервера, токен, самоподписанный сертификат, лимит отображения
  (1…10000), интервал обновления (10…3600 с), проверка подключения;
- светлая и тёмная тема по системной, русский и английский по системному языку.

## Установка

- **Релизы:** https://github.com/sincityview/zabbix-mobile/releases — файл
  `app-release.apk`;
- **свежая сборка из `dev`:** https://github.com/sincityview/zabbix-mobile/releases/download/dev-latest/app-release.apk

Нужен Android 8.0 (API 26) или новее. Обновление поверх предыдущей версии
проходит без удаления приложения: `applicationId` и ключ подписи не менялись.

При первом запуске открываются настройки: адрес вида
`https://zabbix.example.com` (путь `/api_jsonrpc.php` допишется сам), токен
API (в Zabbix: *Users → API tokens*) и кнопка «Проверить подключение» в шапке.

## Сборка

Нужны JDK 21 и Android SDK (платформа 36).

```bash
cd android
echo "sdk.dir=$HOME/Android/Sdk" > local.properties
./gradlew lint testDebugUnitTest assembleRelease
```

APK: `android/app/build/outputs/apk/release/app-release.apk`.
Без переменной `KEYSTORE_FILE` release подписывается debug-ключом — так
собираются PR-и.

## CI

`.github/workflows/build-apk.yml`:

| событие | что происходит |
|---|---|
| pull request, ручной запуск | `lint` + `testDebugUnitTest` + `assembleRelease` + `assembleDebug`, APK уходит артефактом |
| пуш в `dev` | то же + предрелиз `dev-latest` с обеими APK |
| тег `v*` | то же + релиз с `app-release.apk` |

Секреты репозитория:

| секрет | назначение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore в base64 |
| `ANDROID_KEY_ALIAS` | alias ключа |
| `ANDROID_KEYSTORE_PASSWORD` | пароль keystore и ключа |

CI сам проверяет каждый APK (`apksigner verify`, `zipalign`, sha256, отпечаток
сертификата) и печатает это в сводку прогона.

### Параметры запросов

Набор данных повторяет страницу Problems (`CScreenProblem::getData` в исходниках
Zabbix):

| параметр | значение | зачем |
|---|---|---|
| `suppressed` | `false` | без подавленных (maintenance и ручных) |
| `symptom` | `false` | без проблем-симптомов (правила корреляции) |
| `recent` | `true` | вместе с недавно восстановленными, как в UI |
| `monitored` | `true` | без проблем выключенных хостов и триггеров |
| `skipDependent` | `true` | без проблем зависимых триггеров, у которых мастер в проблеме |

Последние два пункта — причина «дубликатов» в прежней версии на Go/Fyne: API
отдаёт, например, 338 проблем, а страница Problems показывает 245.

## Тесты

`./gradlew testDebugUnitTest` — 19 тестов без Android: нормализация URL,
параметры запросов, дедупликация по триггеру, отбрасывание неотслеживаемых
триггеров, отметка восстановленных, ошибки API, наличие `jsonrpc` в теле
запроса, фильтр по важности, разбор настроек.

## Если что-то не так

**«Приложение не установлено, так как его пакет недействителен».** Дело в
файле, а не в приложении. Проверьте размер: у релизного APK он указан в сводке
прогона CI. Частые причины — скачан zip-артефакт CI вместо APK внутри него
(артефакты GitHub всегда отдаются архивом) или обрезанная загрузка. Сверьте
`sha256` из сводки прогона.

**Не устанавливается поверх старой версии.** Android не понижает `versionCode`.
У Fyne-сборки 0.8.3 он был 13, у нынешних — `10000 + номер прогона`, так что
обновление проходит; если ставите APK из старой ветки разработки — удалите
приложение.

**Число проблем не совпадает с Zabbix.** Счётчик показывает `показано/всего`:
первое число ограничено лимитом отображения из настроек, второе — сколько
проблем подходит под текущий фильтр. Если включён фильтр по важности, Zabbix
для сравнения тоже нужно отфильтровать.

## Ограничения текущей версии

- только токен API (входа по логину/паролю нет);
- нет кеша последнего ответа: при холодном старте список пуст до первого запроса;
- R8/сжатие выключено — APK 7.4 МБ, включим после обкатки;
- иконка обычная PNG, без adaptive icon.
